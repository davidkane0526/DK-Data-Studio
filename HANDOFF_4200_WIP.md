# HANDOFF 4200 WIP

> Branch: `4200`  
> Date: 2026-10-30  
> Status: Phase 1 source implementation is in progress. The generic TCP Host path and the read-only Keithley 4200A KXCI plugin are implemented and source-validated. Android APK build and OPPO Pad Mini ↔ Keithley 4200A-SCS real-device validation are still pending.

## Goal

Integrate Keithley 4200A-SCS KXCI control into DK Data Studio without putting instrument-specific logic into Core. Phase 1 is deliberately read-only:

- generic TCP Host capability for Desktop and Android;
- Android socket creation bound to an explicitly selected Android `Network` / interface (default plugin value: `eth0`);
- Keithley plugin actions: Connect / Identify / Disconnect;
- KXCI identity query: exactly `*IDN?\0`;
- verify manufacturer/model and optionally serial number;
- single serialized command queue;
- no blind retry;
- no SMU/PMU source, sweep, pulse, output-enable, or measurement commands.

The verified bench defaults are `169.254.111.118:1225`, interface `eth0`, expected serial `1498377`.

- `desktop/main-modules/tcp-runtime.js`

  - read timeout + post-first-byte idle timeout;

### Android native TCP Host

- `mobile/src/host/protocol.ts`
  - typed `tcpOpen/tcpExchange/tcpClose` native facade.

## Requirements extension: GUI and flexible transport (2026-10-30)

The instrument address is not fixed. Transport selection must support system routing, Wi-Fi, Ethernet, and a named interface; IP/hostname, port and connect/read timeout are user-editable. The instrument must be re-identified after reconnect and never automatically resume an output-producing operation. Current code implements the configurable connection fields and Android network selection. Preset persistence, automatic network diagnostics and production runtime verification remain pending.

Target GUI modes: IV, transfer, output, repeated bidirectional sweeps, timed read, and module-dependent PMU/CVU modes. Plan parameters must include test kind, number of cycles, channel-to-terminal mapping, start/stop/step or points, source level, compliance, measurement speed, settling/hold delay, triggering, and output-off/fault handling. The user must be able to preview the complete point sequence before running. Enforce conservative validated limits and hardware inventory checks before any commands that energize terminals.

Data pipeline: streamed observations with cycle and point indices, device readings, timestamps, status and provenance; plot append without copying full arrays on every point; incremental raw storage; CSV/JSON export and chart image export via existing DKDS APIs. Stop, cancellation, timeout and disconnect must not silently duplicate points or restart acquisition. Preserve incomplete runs as such.

Do not claim a finished measurement GUI. Only connection-layer improvements have been committed in this iteration. Measurement command compilation and hardware output remain disabled until protocol sequencing, hardware constraints, and device acceptance tests are verified against the official KXCI guide (Tektronix 4200A-KXCI-907-01 Rev. E, March 2025).

## Critical user clarification: instrument-original files and graphs (2026-10-30)

The user specifically requires that the "raw data" and "graph/image" come from **the Keithley 4200A**, not from DKDS processing or generating them. This supersedes any imprecise interpretation of simulation CSV/SVG as product deliverables.

- **Instrument-native raw data**: original Clarius-exported measurement file or exact KXCI measurement response payload (preserve original KXCI bytes even when parsing a separate view); never silently smooth, fit, interpolate, resample, round or regenerate as a claimed original. For a Clarius file, copy exact original bytes.
- **Instrument-native graph**: original 4200A-side Clarius export (e.g. PNG) or independently verified instrument-side graph capture. It is *not* a DKDS scientific-plot rendering or SVG recreation.
- **DKDS live scientific plot**: optional monitoring preview only, explicitly not an instrument original graph; preserve readouts separately.
- **Developer simulation**: not hardware measurements; all local CSV, JSON and SVG exports retain simulation provenance and labels. UI now contains an explicit separate instrument-original archive section with unimplemented status; it does not fake an export action.

Official manual constraint (2025 KXCI manual, Clarius user's guide): Clarius and KXCI cannot run simultaneously. Clarius exports graph and measurement sheets via Save Data. KXCI can expose original measurement readings and draw in its instrument UI; generic remote native graph export is **not verified** by currently reviewed KXCI docs. This is a two-path acquisition requirement, not a single KXCI screenshot command.

Implementation must validate 4200A provenance and provide byte-preserving native file copy using a verified instrument-side transport (e.g. supported file share / manually exported file / tested capture). Do not pretend the KXCI TCP instrument command channel is a universal remote filesystem or screenshot API. UI/download must not relabel derived images or reconstructed tabular data as instrument originals. Plan acceptance tests for exact byte identity (including image metadata), original filename + format, device/run provenance, incomplete file transfer rejection and no silent fallback. See updated plugin README.

GitHub Android CI for earlier commit ec0086e4 completed successfully, confirming build path; the OPPO Pad Mini live installation and any graph retrieval remain unverified.

## Iteration 3 — Android-to-browser read-only instrument gateway

The requested topology is **OPPO Pad Mini USB Ethernet -> Keithley 4200A**, and **OPPO Pad Mini Wi-Fi -> desktop computer web browser**. The Android native server already serves static DKDS assets on `0.0.0.0:45910`. Before this iteration desktop browsers could open the GUI, but `src/web-bridge.js` intentionally rejected TCP for plain browsers.

New implementation in branch `4200`:

- `mobile/plugins/DkdsLanKxci.template`: Android Kotlin `DkdsLanKxci` session owner with independent native TCP sockets; compatible Android `Network.socketFactory` Ethernet/Wi-Fi binding, limited to exact `*IDN?\0`, single paired-browser owner, 120-second idle lease, no command replay, response byte preservation in base64, error cleanup. Contains no actual hardware-output commands.
- `mobile/plugins/withDkdsAndroidNativeHost.js`: inject the above Kotlin template into the Expo-generated native module and extend `DkdsLocalWebServer` with an authenticated JSON endpoint `POST /__dkds_kxci`. The server accepts static GET/HEAD as before and handles bounded POST JSON solely for this endpoint. It checks the stored pairing cookie, Origin/Host match, required `X-DKDS-RPC` header and 4096-byte request limit. RPC is DISABLED if `noKey` is enabled. Pair cookies are HttpOnly + SameSite Strict. Five bad pairing attempts trigger a one-minute lockout. Stop/key rotation close all remote sessions.
- `src/web-bridge.js`: plain browsers use same-origin `fetch` for `tcpOpen`, `tcpExchange`, `tcpClose` while native WebView continues its original React Native bridge. This allows the same 4200A UI Connect/Identify/Disconnect implementation to run from a Wi-Fi desktop browser with instrument traffic sent over the tablet's Ethernet interface.
- `tests/test-keithley-4200-lan-gateway.js`: static generated-Kotlin, authentication, session, command allowlist, and web-bridge contract checks; registered in standard tests + Android CI.
- `mobile/README_ANDROID_CN.md` and plugin README: updated installation steps and exact boundaries.

**Important safety limitation:** LAN remote instrument interface is **read-only identification**. The UI's I–V, transfer, output, timed tests and exported SVG/CSV are currently marked SIMULATION. This does not satisfy the final requirement of full remote instrument execution, real-time acquisition or original 4200A measurement files/Clarius images. That work requires KXCI manual-verified command sequences and independently verified native-file transfer/capture mechanisms.

**Security limitation:** Pairing uses a 4-digit Key and plain HTTP and is intended **only for a trusted private LAN**. Never expose `45910` to public Internet or untrusted WLAN. Before enabling any write/output command, implement substantially stronger pairing/authentication, explicit controller lease with safe stop, hardware output-off handling, stream provenance, audit, and stress tests. Android app may be suspended in background; foreground service/wakelock/reconnect state must be designed for actual long acquisitions.

**Acceptance path:** install new APK from its prerelease, make sure Key is enabled, open Android LAN URL on desktop, connect to `169.254.111.118:1225` using Ethernet mode, identify expected `KI4200A` / serial `1498377` while Wi-Fi stays active. Confirm another paired browser cannot control the same session; raw POST other than `*IDN?\0` must be blocked. Test read errors, disconnects, lockout, key rotation and app lifecycle. CI compilation tests are necessary but not a substitute for this physical verification.
