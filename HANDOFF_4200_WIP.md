# HANDOFF 4200 WIP

> Branch: `4200`  
> Date: 2026-10-30  
> Status: Phase 1 source implementation is in progress. The generic TCP Host path and the read-only Keithley 4200A KXCI plugin are implemented and source-validated. Android APK build and OPPO Pad Mini ↔ Keithley 4200A-SCS real-device validation are still pending.

## Goal

Integrate Keithley 4200A-SCS KXCI control into DK Data Studio without putting instrument-specific logic into Core. Phase 1 is deliberately read-only:

- generic TCP Host capability for Desktop and Android;
- Android socket creation bound to an explicitly selected Android `Network` / interface (default plugin value: `eth0`);
- Keithley plugin actions: Connect / Identify / Disconnect;
- KXCI identity query: exactly `*IDN?\0`;
- verify manufacturer/model and optionally serial number;
- single serialized command queue;
- no blind retry;
- no SMU/PMU source, sweep, pulse, output-enable, or measurement commands.

The verified bench defaults are `169.254.111.118:1225`, interface `eth0`, expected serial `1498377`.

## Implemented files

### Generic Desktop TCP Host

- `desktop/main-modules/tcp-runtime.js`
  - session-based raw TCP using Node `net.Socket`;
  - connect timeout;
  - one active exchange per session;
  - Base64 request/response bridge;
  - read timeout + post-first-byte idle timeout;
  - response byte cap;
  - fail-closed session semantics on exchange error or empty read timeout.
- `desktop/main.js`
  - `tcp:open`, `tcp:exchange`, `tcp:close` IPC handlers.
- `desktop/preload.js`
  - renderer-safe TCP IPC facade.

### Shared plugin Host service

- `src/app/modules/dedicated-plugin-windows.js`
  - publishes generic `tcp` via `ctx.services.require('tcp')`.
- `src/web-bridge.js`
  - maps the same facade to React Native native-host requests on Mobile.

### Android native TCP Host

- `mobile/src/host/protocol.ts`
  - typed `tcpOpen/tcpExchange/tcpClose` native facade.
- `mobile/src/host/useNativeRequestRouter.ts`
  - routes WebView native requests.
- `mobile/plugins/withDkdsAndroidNativeHost.js`
  - Kotlin native implementation generated by the Expo config plugin;
  - uses `ConnectivityManager`;
  - when `interfaceName` is provided, resolves the Android `Network` whose `LinkProperties.interfaceName` matches;
  - creates the socket through `Network.socketFactory`;
  - specified-but-missing interface fails instead of silently falling back to Wi-Fi;
  - blank interface uses the system default socket path;
  - adds `android.permission.ACCESS_NETWORK_STATE`;
  - same fail-closed exchange semantics as Desktop.

### Keithley 4200 plugin

- `src/plugins/keithley-4200/plugin.json`
- `src/plugins/keithley-4200/plugin.js`
- `src/plugins/keithley-4200/README.md`

The plugin is Unit-first and currently exposes only Connect / Identify / Disconnect. It sends `*IDN?\0`, expects `KEITHLEY INSTRUMENTS,KI4200A,...`, and optionally checks serial `1498377`.

## Requirements extension: GUI and flexible transport (2026-10-30)

The instrument address is not fixed. Transport selection must support system routing, Wi-Fi, Ethernet, and a named interface; IP/hostname, port and connect/read timeout are user-editable. The instrument must be re-identified after reconnect and never automatically resume an output-producing operation. Current code implements the configurable connection fields and Android network selection. Preset persistence, automatic network diagnostics and production runtime verification remain pending.

Target GUI modes: IV, transfer, output, repeated bidirectional sweeps, timed read, and module-dependent PMU/CVU modes. Plan parameters must include test kind, number of cycles, channel-to-terminal mapping, start/stop/step or points, source level, compliance, measurement speed, settling/hold delay, triggering, and output-off/fault handling. The user must be able to preview the complete point sequence before running. Enforce conservative validated limits and hardware inventory checks before any commands that energize terminals.

Data pipeline: streamed observations with cycle and point indices, device readings, timestamps, status and provenance; plot append without copying full arrays on every point; incremental raw storage; CSV/JSON export and chart image export via existing DKDS APIs. Stop, cancellation, timeout and disconnect must not silently duplicate points or restart acquisition. Preserve incomplete runs as such.

Do not claim a finished measurement GUI. Only connection-layer improvements have been committed in this iteration. Measurement command compilation and hardware output remain disabled until protocol sequencing, hardware constraints, and device acceptance tests are verified against the official KXCI guide (Tektronix 4200A-KXCI-907-01 Rev. E, March 2025).
